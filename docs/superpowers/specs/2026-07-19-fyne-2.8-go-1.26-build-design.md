# Fyne 2.8 and Go 1.26 Windows Build Design

## Goal

Build both Windows executables with stable Fyne 2.8.0 and the current Go 1.26 toolchain while automatically avoiding incompatible or wrong-architecture MinGW compilers on this workstation.

## Confirmed environment

- `C:\Program Files\Go\bin\go.exe` is Go 1.26.5 for `windows/amd64`.
- The first GCC on `PATH` is Simcenter's 32-bit `mingw32` compiler and cannot build the 64-bit CGO application.
- `C:\msys64\ucrt64\bin\gcc.exe` targets `x86_64-w64-mingw32`, but GCC 16.1.0 causes Go 1.26.5's `runtime/cgo` step to exit with status 2.
- `C:\TDM-GCC-64\bin\gcc.exe` targets `x86_64-w64-mingw32`; GCC 10.3.0 successfully builds the Fyne executable with Go 1.26.5.
- PowerShell script execution is disabled by the machine policy, so repository builds must continue through `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\build.ps1`.

## Design

`build.ps1` will retain its `-CCPath` and `-CXXPath` escape hatches. Automatic resolution will prefer the confirmed-working TDM GCC pair, then consider MSYS2 candidates and finally scan `PATH`. Every candidate, including hard-coded paths and explicit overrides, must report an `x86_64` MinGW target through `-dumpmachine`; invalid candidates are skipped automatically, while an invalid explicit override produces a precise error.

The module will declare Go 1.26 and use Fyne v2.8.0, the latest stable Fyne 2.8 release available from the Go module proxy. `go mod tidy` will make the indirect dependency graph match Fyne 2.8.0.

## Error handling

If no suitable compiler is found, the build stops with installation and override guidance. If `g++.exe` cannot be inferred beside the chosen GCC, the build stops and explains how to pass `-CXXPath`. Existing non-zero `go build` handling remains unchanged.

## Verification

Verification must run with the repository's documented PowerShell bypass command. It will assert that automatic resolution prints the TDM GCC pair, run `go test ./...`, build both `fynehmi.exe` and `mockserver.exe`, inspect each binary with `go version -m`, and confirm both output files are valid Windows applications through `Get-Command` and PE header inspection.
